# Owner-bound Personal channels

Each configured text room has an explicit guild/channel/category, owner user ID and identity role ID in `personal_channels`. These are server-side bindings, not values accepted from buttons. A reusable violet panel provides Lock, Unlock, Hide, Unhide, Add member, Remove member, Set status and Clear status with animated custom emoji. Startup refreshes the tracked bot-authored message in place; only a confirmed missing message allows a replacement.

Every interaction fetches the current room and server membership, validates guild/category/message bindings and requires the owner or current Manage Server staff. Guests cannot use controls. Channel ownership, bot access and native Discord Administrator behavior cannot be removed. Panel owners receive only ordinary text access through a member overwrite; native Manage Channels/Manage Roles privileges are not granted to them.

Lock denies ordinary posting and thread writing/creation across role/member overwrites, retaining owner/bot access. Hide denies View Channel across role/member overwrites except owner and bot; Administrator always bypasses Discord channel overwrites. Unhide restores the original private audience and managed approved guests. Everyone always retains an explicit View Channel deny. Original view/write bits are snapshotted before entering a restricted state, while unrelated permission bits are preserved. External administrators can still change native channel permissions; this is not intended to override server administrators continuously.

Adding/removing members uses an ephemeral, actor/channel/server/panel-bound random 128-bit session, expiring after 120 seconds and consumed atomically. Membership and authorization are rechecked on submission. Bots, owners and administrators are excluded from guest changes; administrators already have unavoidable native access. Removal creates a member-level deny so a matching identity role cannot bypass removal. At most 30 guest/block entries are retained per room. An approved guest remains hidden while the room is hidden and read-only while locked.

Text channels do not have a native voice-channel status: Set status uses a one-line 1–100 UTF-16-character topic suffix and panel field. Clearing restores the base topic, preserving externally edited topics. Mentions/control characters are rejected; all panel and interaction payloads suppress mentions. Set status uses the same expiring one-use form binding and fresh owner/staff authorization. Empty statuses omit the optional modal prefill, rather than sending an invalid zero-length value. Topic updates use a topic-only Discord payload and never rewrite channel permissions.

Permission/topic intent is persisted before the Discord update. A failed or ambiguous HTTP update remains pending and visible in the panel; retrying the same explicit control reapplies that private policy. Permissions are not replayed automatically on startup. Pending topic and permission updates cannot overwrite each other; retry the matching control first. A two-second actor/channel limit bounds new controls, while single-use submissions do not add an extra click delay. Sessions are capped at 200 and cleaned every minute after expiry; control-rate records expire after one day. Room ownership, flags, topic status, original permissions and member grants/blocks persist until staff removes/reconfigures the room. No message contents are stored by this feature.

Security regression tests cover actor/channel/server binding, expiration and replay, guests without owner privileges, owner/bot protection, role/member allow bypasses, lock/hide restoration, preserving unrelated permissions, persistent throttling, bounded status values and external topic edits. Live verification checks panel publication, eight controls, scoped owner bindings and unchanged private audiences without granting test guests access or impersonating owners.

Live owner UI verification on 15 October 2026 opened the empty status form, set Ready, and cleared it. The original topic and exact channel permission overwrites were restored and compared against a private snapshot. All 105 tests and strict Clippy passed on Windows and EC2.
