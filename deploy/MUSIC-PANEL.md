# Listening Room — v0.7.0

The shared music panel now has a dedicated 1200×600 monochrome vinyl/doodle card using bundled Space Grotesk, IBM Plex Mono and Kalam. It includes bounded track/artist text, elapsed/duration progress, playback status, volume, repeat state, human listener count and three upcoming tracks. Live sources show LIVE instead of a fake duration. The embed includes requester, voice channel, votes and total upcoming duration (variable when a live source is queued). Valid supported source links remain clickable. No external artwork is fetched.

Four rows contain 14 buttons and a six-preset volume menu. Controls cover pause/resume, skip, vote skip, volume ±10, back/forward 30 seconds, restart track, loop Off/Track/Queue, shuffle, full queue (all 50 supported entries with shortened titles), track details, a control guide and stop/leave. The current state determines labels, active styles and disabled buttons; live/non-seekable/zero-length tracks disable seeking, queues shorter than two disable shuffle, and volume-bound controls disable at 0/100. All button icons use the application-owned animated emoji.

Existing permissions remain: the bot-owned current panel and text channel must match; the member must be in the same voice channel; configured DJ role or Manage Server is required for mutations, while listeners can inspect, read help and vote. Existing two-second control throttling and serialized mutations remain. Volume selections validate an exact allowed preset. All replies are private and mentions are disabled. Seeking obtains a fresh player position, checks the Lavalink request ID, rejects changed tracks, clamps to valid duration, then patches the player. Unknown seekability fails closed.

The existing approximately 15-second update loop edits one message and replaces its image, rather than posting repeated panels. Stop/leave, empty-channel cleanup, queue completion and failed-panel-deletion retries retain existing behavior. A service restart resets the in-memory playback session; no playback is started by deployment. Live listening, source availability and interactive DJ/seek flows require member testing.

Regression checks cover seek bounds/unsupported sources, state-sensitive controls and custom icons, untrusted metadata/Discord field sizes, invalid source links and native PNG rendering. `--preview` writes previews/listening-room.png with clearly illustrative sample track metadata. There are still 100 top-level commands; new controls do not require new slash commands.
