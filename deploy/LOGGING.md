# Activity desk — v0.6.0

`/log enabled:true channel:#auto-log` configures the destination; `enabled:false` disables it and clears the message cache. The existing destination is retained on upgrade and receives a versioned illustrated header. Dedicated log-reader roles remain supported. Setup requires Manage Server, a server text channel with an explicit @everyone View Channel deny, and bot access, Embed Links, Attach Files and Read Message History. Audit attribution additionally requires View Audit Log.

Coverage: human message edits (before/after), deletions and bulk deletions, attachment URLs, voice join/leave/move and mute/deafen/camera/stream changes, member joins/departures, cached role/nickname/server-avatar/screening/timeout changes, uncached member update notices, bans/unbans, channels and threads, permission overwrite differences, roles and permission bitsets, selected server settings, invites, webhook changes, emoji/sticker counts, plus Discord audit events with supplied actor/action/target/reason/reference. Bot moderation case receipts remain separate from gateway observations and Discord audit evidence. Older duplicated plain server-event notices are removed.

Each entry uses the custom animated icon for its event family, timestamps, bounded fields, stable IDs and disabled mentions. Long cached message text is attached as a bounded transcript. The setup header uses the same monochrome fonts and doodle artwork as the other panels. Invite codes, webhook URLs/tokens and arbitrary audit change payloads are omitted.

Message content stays in RAM only: at most 1,000 entries, each text capped at 8,192 UTF-16 units, for up to 24 hours; expiry is checked when messages are processed. Restart loses the cache. Bot/webhook message bodies and activity in the log channel are excluded. Discord log messages/transcripts have independent retention and must be deleted by staff. No audio is recorded. Logs cannot recover messages the bot never observed or events missed while offline. Unknown actors and unavailable baselines are labelled explicitly. Audit entries are separate evidence and are never guessed onto a nearby deleted-message event.

Activity logs stop if the cached destination no longer has the required privacy deny; the central moderation sender also rechecks the channel through REST. Other explicitly configured security/review notices retain their own destination checks. Restrict every allowed reader role to people trusted with all logged content. Discord Administrators always bypass channel privacy.

Audit receipt IDs (no message content) prevent replay duplicates and are pruned after seven days when audit events arrive. A failed delivery is recorded in the local service log and releases its audit receipt for a possible gateway replay; this is best-effort logging, not a durable event archive. Gateway intents include Moderation, Invites, Webhooks and Emoji/Sticker updates, plus configured member/message-content intents. Missing permissions or intents limit coverage.
