# Honeypot channel

`/honeypot enabled:true channel:#honeypot confirm:true` arms a dedicated marked trap. Requires Manage Server and Ban Members, a normal text channel that both staff and bot can access, and an accessible separate log destination that explicitly denies View Channel to everyone. The bot needs Ban Members, View Channel, Send Messages, Embed Links, Attach Files and Read Message History. It refuses destinations already used for configured welcomes, reports, counting, announcements or the voice panel. Never use ordinary chat as a trap.

The existing configured warning is upgraded on startup with an original doodle cover, animated warning icon, explicit consequences, and appeal guidance. A stored bot-owned warning panel must still exist before a new action can run. Missing/edited-away warnings, bad destinations, missing permissions and role hierarchy problems block removal and alert staff. Existing member roles and webhook destinations are not changed. Disable with enabled:false; a paused notice replaces the armed warning when editable.

Posts from non-exempt accounts attempt a softban: ban with zero days of message deletion, followed immediately by an unban. This removes a member, including a legitimate person, and is not proof of spam or alternate ownership. Server owner, this bot, webhooks, trusted actor IDs and members with administrator/server-management/role-management/message-management/moderation/ban permissions are exempt. Other bots are not implicitly trusted. Targets at or above the bot cannot be removed. Duplicate triggers for the same member are claimed once and terminal actions have a five-minute cooldown.

The member receives a styled notice before removal is attempted, then that notice is updated with the actual outcome where Discord allows it. Blocked DMs never prevent moderation or cause a false delivery claim. The private log and owner DM report action outcome, member-notice delivery/update and audit receipt status without copying message content into the new action table.

Each action is persisted before the ban with a unique reason containing its triggering message ID. Unbanning checks the current ban reason first. One immediate retry is made for repair failures. A minute worker checks unfinished actions after three minutes; only the exact matching honeypot reason can be unbanned automatically. An unrelated/reasonless staff ban is held for manual review. Failed recovery is bounded to three attempts; ambiguous requests with no visible ban are observed for up to 15 minutes. Actions needing manual attention are reported. Discord does not provide an atomic ban/unban transaction; staff should check urgent/uncertain outcomes.

Action rows retain Discord IDs, timestamps, message IDs, state and recovery attempts for seven days after becoming terminal. No message content is copied into this table. Unfinished actions are preserved for recovery; existing moderation case history and Discord log/DM retention are separate. No members were removed to validate this release.
